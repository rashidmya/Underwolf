# Input 3a Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the production keyboard/raw-mouse input path with reliable exclusive-mode entry, delivery and restoration on Linux/Proton.

**Architecture:** `uw-input` owns portable policy and Windows adapters; `uw-overlay` wires it to the existing bootstrap and a capability-negotiated input session in `uw-game-channel`. Input travels through the helper to a receiver that acknowledges delivery; a game-local watchdog releases capture independently of IPC. Existing v1 communication tests retain their stand-in overlay.

**Tech Stack:** Rust 2024, `windows-sys 0.61.2`, `minhook 0.9.0`, existing serde JSON lines, Wine, Proton 11.0, existing Electron 44.9.1 spike renderer used only as a test adapter.

**Spec:** `docs/superpowers/specs/2026-10-24-input-3a-design.md` (owner-approved).

## Global Constraints

- “Hooks that run on other threads use a bounded, nonblocking path to that owner and an atomic capture flag.”
- “They never wait for IPC, a shared-memory mutex, or a host acknowledgement.”
- “Regaining focus or reconnecting never re-enters automatically.”
- “No work happens under `DllMain`.”
- “production crates must not depend on spike crates.”
- “No launcher, app API runtime, provider port, Windows release, or 32-bit support is included.”
- Input heartbeat interval 100 ms, capture lease 500 ms; Windows build target `x86_64-pc-windows-gnu`.
- Do not touch game data/code, call game functions, or introduce remote-thread injection.
- Keep bootstrap framing version 1 and the 64-byte state v1 block unchanged. Input capability is a separate handshake.
- Phase 3b retains configurable hotkeys, hit-testing, passthrough modes, DirectInput, GameInput and low-level hook fallback.
- Execute in an isolated worktree. Preserve the existing working tree and stop short of claiming a live check passed without the owner's observation.

## Review Focus

1. A queued edit-on must not regain control after alt-tab, hide, disconnect or lease expiry (Tasks 2, 6, 8).
2. A receiver can keep heartbeating while falling behind on input; stale progress must still expire capture (Tasks 3, 10).
3. Raw and legacy input, repeat messages, both Ctrl keys and surrogate text must not duplicate toggles or characters (Tasks 2, 5, 9).
4. Game-side registration/cursor changes during capture must survive release, including a destroyed/replaced window and monitor changes (Tasks 5, 6, 9).
5. A failed hook enable or a stalled UI thread must not free a callable trampoline or falsely acknowledge restoration (Tasks 4, 7, 9).

## Shared contract decisions

### Wire and session

All integers are little-endian. Add input-only message tags, leaving existing tags intact:

| Tag | Direction / payload, in order |
|---|---|
| `0x0110` InputHello | game→helper: `module_version:u32`, `state_layout:u16=1`, `input_version:u16=1` |
| `0x0111` InputWelcome | helper→game: `input_version:u16=1`, `reserved:u16=0` |
| `0x0112` InputState | game→helper: `epoch:u64`, `active:u8`, `reason:u8`, `has_seq:u8`, `reserved:u8=0`, `state_seq:u64`, `width:u32`, `height:u32` (28 bytes) |
| `0x0113` InputBatch | game→helper: `epoch:u64`, `first_seq:u64`, `count:u16`, `reserved:u16=0`, then `count` 24-byte records |
| `0x0114` InputChallenge | game→helper: `epoch:u64`, `nonce:u64`, `through_seq:u64` |
| `0x0115` InputAck | helper→game: `epoch:u64`, `nonce:u64`, `through_seq:u64` |
| `0x0116` CaptureRequest | helper→game: `epoch:u64`, `state_seq:u64`, `request_id:u32`, `on:u8`, 3 zero padding bytes |
| `0x0117` CaptureResult | game→helper: `epoch:u64`, `state_seq:u64`, `request_id:u32`, `code:u16`, 2 zero padding bytes |

`InputHello` replaces the legacy hello only for the real input module. New helper accepts both;
old helper rejects the new type and the module stays passthrough. Input version mismatch fails
negotiation; do not send input or apply capture until `InputWelcome`. No reliance on ignored
trailing hello bytes. A connection owns one session; epoch starts at 1 per module lifetime and
increments on release, reconnect or window replacement, checked for overflow (unavailable on
exhaustion). Sequence numbers start at 1 per epoch. The module stays loaded, so helper restart
does not reset epochs. Counter wrap is never silently accepted.

Each input record is `kind:u8`, `flags:u8`, `reserved:u16=0`, `a:i32`, `b:i32`, `c:i32`,
`d:i32`, `modifiers:u32`. Kinds: 1 key (`a=VK`, `b=scan`, flags bit0 down, bit1 extended,
bit2 repeat); 2 text (`a=Unicode scalar`); 3 move (`a=x,b=y`); 4 button (`a=0..4`,
flags bit0 down, `b=x,c=y`); 5 wheel (`a=horizontal,b=vertical` in native 120-unit ticks,
`c=x,d=y`). Unused fields/flags must be zero. Modifiers bits 0..3 are Shift/Ctrl/Alt/Meta;
reject unknown bits. VK range 1..255; scan 0..65535. Mouse positions are signed client pixels;
outside-window coordinates are valid. Text excludes surrogates and values above `0x10ffff`.
At most 64 records per batch: payload at most 1556 bytes, below existing 4096.

`InputReason` wire values 0..10: Ready, Requested, Hotkey, FocusLost, Hidden, Disconnected,
LeaseExpired, Overflow, WindowDestroyed, SetupFailed, Unavailable. `CaptureCode` values 0..4:
Applied, StaleEpoch, Unavailable, SetupFailed, Superseded. Unknown codes are decode errors.
Use Rust types `InputRecord`, `InputBatch`, `InputState`, `InputChallenge`, `InputAck`,
`CaptureRequest`, `CaptureResult` with fields matching these tables; enum conversions live in
`uw-pipe-proto::input`. `InputRecord` exposes typed constructors and checked decoding.

### State application

The state v1 `edit_mode` remains the helper's requested value, not actual capture. For a negotiated
input module, an edit-bearing `set_state` also sends a `CaptureRequest` with current epoch and
the resulting state sequence and original request id, even if the stored boolean was already
equal. Results carry that id to distinguish same-value requests sharing a sequence. The real module
ignores `edit_mode` in doorbells: only an epoch-checked request may enter capture. Visibility
still uses the state block; hiding releases locally. For commands containing visibility and
edit mode, read the latest state before entry; hidden always wins.

Keep `StateSet` as the existing acceptance reply. Add actual-state/result events; never label
`StateSet` an application acknowledgement. Set `applied_seq` only after the UI transition is
finished. Queue accepted sequences in order (capacity 32); visibility/state coalescing may mark
an obsolete request Superseded, but it cannot mark it Applied. Results carry the request's epoch,
including stale results; current actual state is reported separately. A loss increments epoch before
new commands can enter; requests still queued for the previous epoch return StaleEpoch.

JSON additions (all serde snake_case): `InputReady {version}`, `InputState {state: InputState}`,
`InputBatch {batch: InputBatch}`, `InputChallenge {challenge: InputChallenge}`,
`CaptureResult {epoch,state_seq,capture_request_id,code}`, and `InputAcked {request_id}`. Command
`InputAck {request_id,ack: InputAck}` is the sole new JSON command. Input acknowledgements
still get one acceptance reply, and request-id helpers recognize it. Internal transport structs
derive serde with explicit stable field names. JSON is a test/client interface, not Overwolf API.
Add optional `input_epoch: Option<u64>` to `Command::SetState` (serde default/skip-none).
For negotiated input modules, edit-bearing requests require it and reject missing/stale epochs
before mutating state. Legacy modules ignore it. The receiver supplies the epoch it observed;
never stamp an old queued request with a new epoch on its behalf. Initial/reconnect reconciliation
for input modules sends visibility only; capture already starts off. Update all existing Rust
SetState constructors with `input_epoch: None` and patterns with the field or `..`.
`capture_request_id` is correlation metadata for the second, unsolicited application result,
not a second pending-command reply; CLI retains its user-id mapping until this result or loss.
Bound these retained capture correlations to 32; refuse further capture requests while full,
and report an application timeout after 5 seconds without claiming application succeeded.
Clear correlations on session loss. Late results remain diagnostic and cannot alter actual state.

### Queues and progress

Game event queue: 1024 records, nonblocking producer using a preallocated buffer with `try_lock`;
only adjacent moves may replace the last unsequenced move. Assign sequence on dequeue after
coalescing. Lock contention or capacity failure on a discrete event revokes capture. Droppable
move contention does not fabricate movement. A separate atomic release latch and latest state
mailbox cannot be crowded out by event traffic. Control queue capacity 32; saturation revokes
capture and closes the session. Clear old-epoch records before publishing the new epoch.

Maintain at most eight outstanding challenges, sent every 100 ms even while inactive, with
game-local issue time and the highest input sequence sent before the challenge. A response is
valid only for the current epoch and a known, unexpired nonce with `through_seq` equal to that
challenge's advertised value. Consume each nonce once. Lease age is measured from **challenge
issue time**, not acknowledgement arrival, so buffered acknowledgements cannot extend it.
Accept the latest valid acknowledgement monotonically; older acknowledgements never regress
progress. Capture requires a valid acknowledgement less than 500 ms old. At age >=500 ms,
revoke capture. This also works at idle (`through_seq=0`). The receiver acknowledges a challenge
only after it has consumed all preceding records in that epoch. A newer heartbeat cannot skip
undelivered input. Watchdog checks every 10 ms, independently of the IPC worker; deadline is
500 ms plus scheduling delay, not a hard real-time guarantee.

Forwarding queues in helper and host are bounded to 64 input batches. Overflow disconnects the
input session (ordinary control/game data must not be silently discarded). Never manufacture
receiver acknowledgements in the helper, host supervisor, CLI stdout writer, or a background
thread detached from actual receiver progress.

### Hook coverage and ordering

| Surface | Owner/thread | Capture behavior / proof |
|---|---|---|
| `WH_KEYBOARD`, `WH_MOUSE` thread hooks | game UI thread | Observe/chord and swallow only the selected game window; negative hook code always chains |
| WndProc | game UI thread | Handle focus, destroy, transition messages and text; no duplicate forwarding of hook-owned key/mouse events |
| `GetKeyState`, `GetAsyncKeyState`, `GetKeyboardState` | any caller | Neutral pressed bits; preserve toggle bits, output/error contracts and real-state bypass for the module |
| `GetRawInputData`, `GetRawInputBuffer` | any caller | Call originals; preserve queries/errors/counts; neutralize keyboard/mouse, preserve HID and release records |
| `RegisterRawInputDevices` | any caller | Track only successful intended requests; apply capture transform, restore latest intent |
| `GetCursorPos`, `SetCursorPos` | any caller | Frozen game-visible position; overlay samples actual position through original function |
| `ClipCursor`, `GetClipCursor` | any caller | Record game intent; keep pointer free for overlay; release clip on focus loss |
| `ShowCursor`, `SetCursor`, `GetCursor` | caller, UI transition owner | Keep game-visible counter/shape coherent; restore only our adjustments and latest intent |

Canonical host key/button/wheel source is the thread-hook legacy stream enabled by removing
NOLEGACY; text is WndProc character messages. Raw input is suppression/accounting only and is
never forwarded a second time. Motion is sampled in client pixels from the original cursor
function on legacy movement; no accumulation of relative raw deltas. If an entry cannot establish
this path, refuse capture instead of claiming that raw-only input works. Raw keyboard suppression
must preserve record processing/cleanup; the exact Win32 neutral record treatment needs the
real-API tests in Task 5, not a synthetic struct-only assertion.
