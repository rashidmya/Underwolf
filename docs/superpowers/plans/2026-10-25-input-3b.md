## Global Constraints

- “The injected module owns hit-testing and input decisions.”
- “No automatic recapture after focus loss, hiding, delivery loss or reconnect.”
- “No game data/code changes, calls to game functions, remote-thread injection, or production dependencies on spike crates.”
- “Dirty-rectangle frame transport and the full overlay performance gate remain roadmap item 4.”
- “Do not reinterpret v1 records or the existing 64-byte state block.”
- “Do not hook under `DllMain`, patch game code, or run API calls while holding the policy lock.”
- “Never unregister a callback synchronously from inside itself.”
- Matching 3b input-capable host/helper/DLL builds; input version 2; bootstrap framing/state layout remain version 1. Keep the state-only test overlay and game-data protocol working.
- At most 32 widgets, 64 bindings, 64 records/batch and 4096 payload bytes/message. Heartbeat 100 ms, lease 500 ms; all counters checked for overflow.
- Target `x86_64-pc-windows-gnu`; Linux/Proton delivery first. No launcher, app API runtime, persistence, production layout editor, Windows release, 32-bit support or XInput work.
- Capture callbacks never allocate or wait for IPC/shared locks/receiver progress. Preserve 3a's immediate permission revocation and deferred UI restoration boundary.
- Every native FFI detour retains a panic boundary and resident callable originals; Rust panic recovery does not claim to catch memory faults.
- Native adapter absence/unsupported ABI is an explicit coverage result, never a passed isolation test. Do not install another runtime into the player's game.
- Execute product changes in an isolated worktree using `superpowers:using-git-worktrees`. Read this plan and its spec before starting. Do not run builds or interact with an active owner game until the owner is available for that work.

## Review Focus

1. Loss/reconnect while a table or takeover request is queued must not restore ownership or let a stationary hover recapture (Tasks 4, 6, 9, 11).
2. Overlapping sided/unsided hotkeys, extra modifiers and a rebind while held must yield one action and a usable exit chord (Tasks 2, 3).
3. Moving/removing/reusing a widget during held input must preserve paired releases or explicit cancellation without reaching the replacement (Tasks 4, 5, 10).
4. Optional DLL loading, pre-existing objects, shared method addresses and callback teardown must never expose an uninstalled input path or free callable state (Tasks 1, 6–8).
5. Retained/history readings and stalled renderer consumption must not leak input; JSON counter precision must not accept a stale epoch or acknowledge unconsumed work (Tasks 2, 5, 8–11).

## Shared contracts

### Routing v2 wire

Leave `input.rs`'s v1 decoder/types available to legacy fixtures. Add
`uw_pipe_proto::routing` with `ROUTING_VERSION: u16 = 2`, separate message tags
and `OverlayMessage::Routing(RoutingMessage)`. A production 3b session rejects
the v1 input hello; it still accepts the separate state-only overlay hello.
No payload with a new shape uses a v1 input tag.

All integers are little-endian; reject unknown flags, nonzero padding, invalid
enums, trailing bytes, count/length mismatches and arithmetic overflow.
`WidgetRef { id: u32, generation: u32 }` requires both fields nonzero; both zero
encode no target. A mixed zero/nonzero pair is invalid. Never recycle a
generation after overflow.

| Tag | `RoutingMessage` variant and payload |
|---|---|
| `0x0120` | `Hello { module_version:u32, state_layout:u16=1, input_version:u16=2 }` (8 bytes) |
| `0x0121` | `Welcome { input_version:u16=2 }` plus two zero bytes (4) |
| `0x0122` | `State(RoutingState)` (60) |
| `0x0123` | `Configure(RoutingConfig)` (32 + 32/widget + 24/binding) |
| `0x0124` | `Configured(RoutingResult)` (32) |
| `0x0125` | `Events(RoutedBatch)` (20 + 48/event) |
| `0x0126`, `0x0127` | `Challenge(InputChallenge)`, `Ack(InputAck)` using their existing 24-byte field layout |
| `0x0128` | `Request(RoutingRequest)` (40) |
| `0x0129` | `Result(RoutingResult)` (32) |
| `0x012a` | `Coverage(NativeCoverage)` (32) |
| `0x012b` | `Visibility { state_seq:u64, on:bool }` plus seven zero bytes (16) |

`RoutingConfig { epoch:u64, revision:u64, request_id:u32, width:u32,
height:u32, widgets:Vec<WidgetSpec>, hotkeys:Vec<HotkeySpec> }` encodes a
32-byte prefix (counts are u16) followed by the tables. Epoch/revision/id and
client dimensions are nonzero; dimensions fit i32. Widget geometry arithmetic
uses i64. Zero-size widgets are legal but ineligible; negative dimensions are
invalid. Hidden/off-client targets remain valid table references.

`WidgetSpec` is 32 bytes: instance (8), `x/y/width/height:i32` (16), `z:i32`
(4), `mode:u8`, `flags:u8` (visible bit0, keyboard-eligible bit1), two zero
bytes. `InputMode` values: Block=0, Pass=1, Notify=2. Widget instances, numeric
ids and z values are unique across a snapshot.

`HotkeySpec` is 24 bytes: `id:u32`, `vk:u16`, `modifiers:u16`, `flags:u16`,
`action:u16`, target (8), four zero bytes. Modifier bits come in four groups
of three (Shift, Ctrl, Alt, Meta): either/left/right. Either cannot coexist
with a side requirement; left+right means both. Flags: passthrough bit0,
allow-extra-modifiers bit1. Match only keyboard VKs 1..255, excluding mouse
VKs and modifier keys as primary triggers. Actions: ToggleEdit=1, Notify=2,
Takeover=3, ReleaseTakeover=4. The first two have no target; the latter two
reference a widget. Require exactly one ToggleEdit. Detect overlapping
matches by enumerating all 256 physical left/right modifier states for each
primary key outside the hook path. Thus generic Ctrl and left Ctrl cannot
silently compete for the same press.

A full config is `32 + 32*32 + 64*24 = 2592` bytes. There is no fragmentation,
truncation or string name on the binary path. Host maps numeric ids to names.

`RoutedEvent { revision:u64, target:Option<WidgetRef>, kind:EventKind,
argument:u32, input:Option<InputRecord> }` encodes 48 bytes: revision (8),
target (8), kind u8 + three zero bytes (4), argument (4), existing 24-byte
input payload. EventKind Input=1 requires a target and valid input, argument
zero; Hotkey=2 has no target, argument=binding id; Cancel=3 targets an
instance, argument=existing `InputReason`; Focus=4 targets an instance,
argument=0/1 for loss/gain; Leave=5 targets an instance, argument=0. Non-input
payloads are all zero. `RoutedBatch { epoch:u64, first_seq:u64,
events:Vec<RoutedEvent> }` uses a 20-byte prefix. Max batch is 3092 bytes.
Input coordinates in targeted records are widget-local physical pixels.

`Domains { keyboard:bool, mouse:bool }` encodes bits 0/1. `RoutingState`
contains epoch/revision/state_seq (three u64, zero sequence when absent),
width/height (two u32), pointer/focus/takeover (three optional WidgetRef),
then flags u8 (exclusive bit0, has_state_seq bit1), domains u8, reason u8,
and one zero byte. Revision zero is valid only before configuration. Invalid
field combinations and unknown reason values are errors.

`RoutingRequest { epoch, revision, request_id, target, action, state_seq }`
encodes two u64, request id u32, target (8), action u8, has_seq u8, two zero
bytes, state_seq u64. Actions EnterEdit=1, LeaveEdit=2, Takeover=3,
ReleaseTakeover=4; only takeover actions carry a target. `RoutingResult`
contains epoch u64, revision u64, request id u32, code u16, two zero bytes,
and `through_seq:u64`. Codes Applied=0, StaleEpoch=1, StaleRevision=2,
Invalid=3, Unavailable=4, SetupFailed=5, Superseded=6, NotOwner=7.
Configuration and takeover results have separate tags/correlation maps.

`NativeCoverage` contains epoch u64, discovery revision u64, then DirectInput
and GameInput descriptors of eight bytes each: status u8, domains u8,
abi_mask u16, detail u32. Status Absent=0, Installing=1, Supported=2,
Unsupported=3, Failed=4. DirectInput ABI bits identify 8A/8W; GameInput bits
identify v0/v1/v2/v3. A domain is advertised only when all discovered routes
for it are covered. Absence is compatible with the Win32 path, but not a
native acceptance pass.

All routing JSON u64 values are canonical decimal strings, validated as
u64; ids/u32 geometry/count fields stay JSON numbers. Do not pass u64 counters
through JS Number. New JSON commands: `configure_input {request_id,config}`,
`route_request {request_id,request}` and `routing_ack {request_id,ack}`.
Require inner/outer configuration/request ids to
match. New events: `routing_ready {version}`, `routing_state {state}`,
`routing_configured {result}`, `routed_batch {batch}`, `routing_result
{result}`, `input_coverage {coverage}`, `routing_challenge {challenge}` and
`routing_acked {request_id}`. V2 JSON adapters serialize the shared
InputChallenge/InputAck counters as strings at the new envelope fields;
v1 JSON names and their numeric representation remain separate. Errors
continue to use existing `Event::Error`.

### Ordering and policy

Validate/compile tables outside the hook, then queue one immutable
`PreparedConfig` to the UI owner. Queue capacity is 32; full means rejection,
never overwrite. Publication and native effects happen outside the policy
lock. Owner application checks current epoch/lease/geometry again.

`Router` owns widget focus, pointer capture, instance pairing and takeover
identity. `Policy` remains the authority for physical/game-held state and
lifecycle. `HotkeyMatcher` receives that real state and never independently
polls filtered APIs. Route effects include at most 35 events per operation
(32 cancellations plus focus/action); reserve all required slots together.

Use a worker-owned ordered stream of events and configuration/result barriers.
On a healthy reconfiguration, send old-target cancellation events first,
then Configured with their ending `through_seq`, then events using the new
revision. Receiver retirement waits for those preceding events to be consumed.
Unrelated geometry revisions must not discard previously routed releases.
If capacity cannot preserve the barrier, revoke and reset the epoch instead.
Reserve 64 control/barrier entries independently of 1024 input-event slots;
if control capacity itself is exhausted, use 3a's independent release/status
signal and disconnect. Moves coalesce only when target, generation and
revision are identical and no event/barrier intervenes.

Initial configuration does not take ownership. In standard mode with a real
visible, unconstrained game cursor, a fresh click arms an interaction; no
stationary hover arms it. Once armed, eligible hover/capture selects pointer
ownership; leaving all blocking targets releases the mouse domain while
focused keyboard ownership follows the focus rules in the spec. A confined or
hidden FPS pointer requires an explicit exclusive-mode request. Configuration,
visibility changes and reconnect cannot arm interaction.

Exclusive mode blocks both domains, makes all visible widget bodies eligible,
and consumes the complete background-click pair on exit. Standard-mode game
click clears widget focus and is forwarded. Notification is passive: no
cursor/registration changes or synthetic game releases. Domain entry performs
3a's successful setup/release sequence before advertising ownership; partial
setup rolls back. Domain exit retains held-until-up suppression.

Optional module notification clears the atomic ownership permission before
returning, queues discovery work only, and never installs hooks under the
loader lock. Re-establishing coverage does not recapture. Runtime/table
updates are committed by the UI owner; native readers consult one coherent
epoch/domain snapshot and use originals when ownership is not permitted.

Ordinary focus/domain transfers within a healthy capture preserve its epoch
and carry ordered cancellation/state changes. Releasing the complete capture,
disconnecting or losing eligibility advances the epoch with checked arithmetic,
as in 3a. Previously accepted configuration may remain as immutable data during
a local release; it supplies no authority to recapture. Reconnect requires a
new epoch-scoped publication. No table request admitted under the old epoch
can commit under the new one.

### Native ABI boundary

Use narrow borrowed raw COM declarations under `win/abi`, with the existing
`windows-sys` structs/constants and `extern "system"` signatures. Add its
`Win32_Devices_HumanInterfaceDevice` and `Win32_System_Diagnostics_Debug`
features only as needed; no additional COM wrapper crate is required.
Never construct an owning projected COM value from a borrowed game pointer.
Every retained native reference has a matching original AddRef/Release.

DirectInput 8A/8W declarations follow the installed MinGW `dinput.h`, checked
against Microsoft's published method contracts. Discovery creates its own
unacquired keyboard/mouse objects and records their actual system method
addresses. Hook shared implementations, not per-game vtable bytes; deduplicate
identical address/signature pairs. An incompatible alias fails installation.

GameInput declarations follow Microsoft header commit
`dce6dabd75b53fcb29db86afe4de5c917921af18`: `include/v0/GameInput.h`,
`include/v1/GameInput.h`, `include/v2/GameInput.h`, `include/GameInput.h` (v3).
The exported factory returns the legacy interface; obtain each supported
version with its actual IID via QueryInterface, including aliases returned
later. Never select a layout from only the DLL filename or version string.
Use header-specific callback signatures; v0's unregister timeout differs
from later versions. Native probes must call through independently declared
interfaces, including factory-before-install objects.

Freeze keyboard, mouse and structured GameInput controller/gamepad/arcade/
flight/racing readings in exclusive mode; standard mode filters only owned
keyboard/mouse domains. Preserve input kind, device identity and timestamps;
neutralize action values without changing structural counts. Raw opaque,
touch, motion, sensors or another unimplemented active accessor is not silently
passed during claimed isolation: report its coverage unsupported and revoke.
This does not provide controller routing to widgets or XInput isolation.
