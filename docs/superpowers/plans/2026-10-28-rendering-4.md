# Rendering 4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver production Linux widget rendering with correct accumulated dirty rectangles, GPU-safe shared-buffer ownership, and measured whole-overlay overhead at or below 3%.

**Architecture:** A portable frame protocol describes per-widget state. An Electron producer and native Linux Vulkan consumer share separate metadata and pixel memfds, with one outstanding GPU upload per widget. ## Global Constraints

- Linux/Proton first; native Linux Vulkan compositing inside the game frame.
- Production code must not depend on `spikes/*`.
- The injected Windows module remains the sole authority for hit-testing and input capture.
- No game data/code modifications, game-function calls or device-wide idle waits.
- Keep Electron 44.9.1 and the existing CPU BGRA8 premultiplied/sRGB path.
- Use one outstanding upload per widget; consumption means matching GPU completion.
- 32 widgets, 4096 pixels per side, and 256 MiB of shared pixels per session including retired allocations.
- No lower widget frame rates or GPU shared textures to rescue the performance gate without a separate scope decision.
- GameInput remains deferred. App runtime, provider, launcher, catalog, Windows rendering and packaging remain outside this phase.
- Live benchmarks require a coordinated game session. Do not operate a running owner game as part of planning or isolated tests.

## Review Focus

- A static widget changes while its previous upload is in flight and never paints again: retained pixels must flush after completion (Tasks 2, 4, 6).
- A producer dies during a row write, or a completion arrives after ID reuse: reject damaged/stale generations without freeing live GPU memory (Tasks 3, 5, 6).
- Presentation skips, errors, resize and multiple swapchain images: preserve the game's semaphore chain and never acknowledge an unexecuted copy (Tasks 5, 6).
- Non-unit scale, overlapping widgets and transparent clears: agree with input coordinates and preserve unchanged pixels and alpha (Tasks 1, 6, 7).
- Slow/disconnected rendering and a still-responsive input receiver: revoke capture readiness and preserve 3b's actual-consumption lease (Task 7).

## Fixed contracts for all tasks

### Portable types

Define these in `uw-frame-proto` and re-export from `lib.rs`:

```rust
pub struct SessionId(pub [u8; 16]);
pub struct WidgetKey { pub id: u32, pub generation: u32 }
pub struct AllocationKey { pub session: SessionId, pub widget: WidgetKey, pub generation: u64 }
pub struct Rect { pub x: u32, pub y: u32, pub width: u32, pub height: u32 }
pub struct FrameLayout { pub width: u32, pub height: u32, pub stride: u32, pub pixel_len: u64, pub alignment: u64 }
pub enum FrameError { Invalid, Bounds, Overflow, Version, Stale, Busy, Unsupported, Capacity, OwnerDied, Io }
pub enum Phase { Idle, Ready, Reading, Invalid }
pub struct Claim { pub key: AllocationKey, pub seq: u64, pub damage: Rect }
pub struct FrameState { /* private fields; serialized under the shared mutex */ }
```

Signatures: `Rect::checked(x, y, width, height, bounds: (u32,u32)) -> Result<Option<Rect>,FrameError>`;
`Rect::union(self, other: Rect) -> Rect`; `FrameLayout::new(width, height, alignment) -> Result<FrameLayout,FrameError>`;
`FrameState::new(key, layout) -> Self`; `publish(&mut self, seq, damage) -> Result<(),FrameError>`;
`claim(&mut self) -> Result<Option<Claim>,FrameError>`;
`complete(&mut self, claim: Claim) -> Result<(),FrameError>`;
`cancel_unsubmitted(&mut self, claim: Claim) -> Result<(),FrameError>`;
`invalidate(&mut self)`; `snapshot(&self) -> StateSnapshot`. `StateSnapshot` exposes
key/layout/phase/produced/consumed/claimed/damage/baseline for validation/tests.

All identities/counters are nonzero except initial frame counters. A session is
16 random nonzero bytes. Frame sequences can skip, but increase strictly when
published. Invalid generations never recover in place. The first ready damage
covers the whole frame; patches may merge into that ready full publication before
its first consumption. Completion sets baseline=true and clears only that claim.
Reading rejects publication with `Busy`; cancelled unsubmitted claims return to
Ready with their original damage and do not advance consumption.

BGRA8 format code is 1. Stride is `align_up(width * 4, 64)` (maximum 16,384).
Require host page size 4096 and negotiated power-of-two import alignment in
`[4096, 1_048_576]`. `pixel_len = align_up(stride * height, alignment)` with checked
arithmetic. Align the layer mapping address as well as allocation length. An
unsupported page/ABI/alignment gets a diagnostic, never a guessed mapping.

### Shared-memory layout v1

Two size-sealed memfds per allocation: 4096-byte control and `pixel_len` pixels.
Metadata is never imported into Vulkan. Require `F_SEAL_GROW | F_SEAL_SHRINK |
F_SEAL_SEAL` before sharing, but not write seals; both processes must update state.
All encoded integers are little endian. Do not use a Rust struct cast for bytes.

| Offset | Bytes | Field |
|---|---:|---|
| 0 | 4 | `UWFC` |
| 4 | 2 + 2 | format version 1, header bytes 256 |
| 8 | 16 | session ID |
| 24 | 4 + 4 | consumer Linux pid, producer Linux pid |
| 32 | 8 | consumer `/proc/<pid>/stat` start ticks |
| 40 | 4 + 4 | widget id and widget generation |
| 48 | 8 | allocation generation |
| 56 | 4 + 4 + 4 + 4 | width, height, stride, format 1 |
| 72 | 8 + 8 | pixel_len, import alignment |
| 88 | 2 + 2 + 4 | mutex size 40, alignment 8, ABI code 1 (Linux x86_64/glibc) |
| 96 | 32 | reserved zero |
| 128 | 64 | initialized robust process-shared pthread mutex; unused padding zero |
| 192 | 8 + 8 + 8 | produced, consumed, claimed sequence |
| 216 | 4 + 4 + 4 + 4 | damage x, y, width, height (zero rect = none) |
| 232 | 4 + 4 + 4 | phase (Idle=0/Ready=1/Reading=2/Invalid=3), baseline flag 0/1, invalid reason code |
| 244 | 12 | reserved zero; rest of the control page reserved zero |

Before using the mutex, verify initialized registration, both file extents and
seals, header bytes, exact session/peer identity, supported native mutex size and
alignment, reserved fields, allocation budget and layout. Retain a validated
private copy of immutable metadata for all address arithmetic. The mutex is a
native local ABI object, not a portable wire object; initialization must succeed
before either FD is sent. No mutex reset/destruction while another process can
access it. `EOWNERDEAD` or `ENOTRECOVERABLE` invalidates the allocation; never use
its pixels or attempt to repair its old publication.

### Socket protocol v1

The 16-byte header is `UWFR[4], version:u16=1, type:u16, payload_len:u32,
fd_count:u16, reserved:u16=0`. Payload <=4096; attached FDs <=2. Wire encoders use
explicit integer fields, not enum-layout serialization. Reject extra bytes/FDs,
unknown tags and malformed/truncated ancillary data; close all received handles
on every error. Loop on partial sends without sending descriptor rights twice.

Message fields below are encoded in listed order, tightly packed. `AllocationKey`
is 32 bytes (session[16], widget id/generation u32 each, allocation u64);
`WidgetKey` is 8. Booleans are one byte 0/1. All payloads must consume exactly the
message's declared length.

| Tag | Message payload | FDs |
|---:|---|---:|
| 1 | Hello: pid:u32, start_ticks:u64, alignment:u64, mutex_size:u16, mutex_align:u16, abi:u32, capability:u32 (0 unavailable / 1 coherent import and safe presentation retirement) | 0 |
| 2 | Welcome: session[16], producer_pid:u32, max_widgets:u32=32, max_side:u32=4096, shared_budget:u64=268435456 | 0 |
| 3 | Register: the immutable first 128 control bytes | 2, control then pixels |
| 4 | Dirty: AllocationKey, produced:u64 | 0 |
| 5 | Consumed: AllocationKey, consumed:u64 | 0 |
| 6 | Layout: WidgetKey, revision:u64, x:i32, y:i32, width:u32, height:u32, z:i32, visible:u8 | 0 |
| 7 | Remove: WidgetKey, revision:u64 | 0 |
| 8 | Dimming: revision:u64, active:u8 | 0 |
| 9 | NeedBaseline: WidgetKey | 0 |
| 10 | Unavailable: AllocationKey (all zero for session errors), reason:u32 | 0 |
| 11 | Retired: AllocationKey | 0 |
| 12 | Registered: AllocationKey | 0 |
| 13 | Swapchain: generation:u64, width:u32, height:u32, ready:u8 | 0 |
| 14 | Progress: swapchain_generation:u64, completed_draw:u64, monotonic_ns:u64 | 0 |

`Registered` means descriptor/import preparation succeeded, not pixels consumed.
Session-wide errors use reasons 1=version, 2=identity, 3=unsupported, 4=capacity,
5=owner-dead, 6=invalid, 7=GPU failure. Dirty/Consumed hints coalesce to the newest
counter per allocation; shared state is authoritative. Retired means no remaining
layer GPU/reference ownership. Dimming/layout revisions are monotonic per session;
they can never resurrect removed instances. NeedBaseline causes a fresh allocation
and full publication from the retained latest image, including for static widgets.

Progress is a coalesced health hint from completed overlay draws, at most every
100 ms, and cannot advance pixel consumption. Its timestamp uses Linux
CLOCK_MONOTONIC. Validate a shared time namespace during handshake; otherwise
report unsupported health-clock configuration. Repeated/stale progress cannot
refresh readiness. A 500-ms render-health timeout or a pending paint older than
500 ms disables capture readiness; the existing input lease is still a separate
game-local release backstop. No new hard native release-time claim follows from
this host-side readiness timeout.

### Channel and addon interfaces

Linux channel public API (`uw-frame-channel`, with a crate-local `Result<T>` alias):

```rust
pub struct FrameMapping { /* owned fds/mappings, validated immutable metadata */ }
pub struct ReadLease { /* Claim and Arc<FrameMapping>, no mutable pixel access */ }
pub enum PublishResult { Published { seq: u64, bytes: u64 }, Busy, Stale }
pub enum CompleteResult { Completed, Busy, Stale }
pub struct Patch<'a> { pub rect: Rect, pub stride: u32, pub data: &'a [u8] }
impl FrameMapping {
    pub fn create(key: AllocationKey, layout: FrameLayout, peer: PeerIdentity) -> Result<Self>;
    pub unsafe fn open(header: &[u8], fds: [OwnedFd; 2], peer: PeerIdentity) -> Result<Self>;
    pub fn try_publish(&self, seq: u64, patch: Patch<'_>) -> Result<PublishResult>;
    pub fn try_claim(self: &Arc<Self>) -> Result<Option<ReadLease>>;
    pub fn try_cancel_unsubmitted(&self, lease: &ReadLease) -> Result<CompleteResult>;
    pub unsafe fn try_complete_after_gpu(&self, lease: &ReadLease) -> Result<CompleteResult>;
}
pub fn send_message(stream: &UnixStream, message: &Message, fds: &[BorrowedFd<'_>]) -> Result<()>;
pub fn recv_message(stream: &UnixStream) -> Result<(Message, Vec<OwnedFd>)>;
```

`PeerIdentity` contains pid:u32, start_ticks:u64 and uid:u32. Completion's safety
contract requires actual completion of all GPU reads of the lease; the layer
calls it only after its fence succeeds. `ReadLease` cannot free/unlock submitted
pixels merely by dropping: submission retains it until safe completion/retirement.
Mutex-busy completion retains the lease and retries outside present. Native open
and writable-descriptor export require an explicit unsafe synchronization contract.
Budget-aware create_in/open_in variants retain reservations inside mappings;
standalone constructors remain available for isolated uses. These execution
rulings and their tradeoffs are recorded in the ledger.

Endpoint: `$HOME/.cache/underwolf/render/<pid>-<start_ticks>.sock`, private parent
directories 0700 and socket 0600. Parse proc stat after the final `)` around comm,
not by fixed whitespace fields. Validate `SO_PEERCRED` uid/pid against Hello and
the selected live process incarnation. One accepted consumer per endpoint; a
second live connection is rejected without replacing the first. Reconnect creates
a fresh session and mappings. Only unlink a socket the binding process owns.

Workers use 100-ms bounded socket wakeups, latest-per-widget notification slots,
at most 128 non-coalescible controls, and a 10-ms completion/retry poll. A critical
control overflow disconnects the session. A socket timeout reports stall, never
consumption. Track live plus retired allocations against the 256-MiB shared budget;
the layer additionally caps tracked GPU/import allocations at 512 MiB, descriptor
sets at 512, presentation records at 256 and swapchain image slots at 8. Fail
capacity cleanly rather than grow
graveyards indefinitely. Reject unsupported queue/capability paths explicitly.

Bridge (`node` feature) exports synchronous, non-waiting operations:

- `startServer({ pid:number, startTicks:string }): void`; resolve the endpoint natively.
- `createWidget({ id,generation,width,height }): FrameKeyJs`; native allocation counter.
- `publishPatch({ key,seq:string,x,y,width,height,stride,data:Buffer }): PublishResultJs`.
- `canPublish(key): boolean` is a hint; publish always rechecks under `try_lock`.
- `setLayout({ widget,revision:string,x,y,width,height,z,visible }): void`.
- `setDimming({ revision:string,active }): void`; `removeWidget(widget,revision:string): void`.
- `drainEvents(): BridgeEvent[]` (<=128), `stats(): BridgeStats`, `stop(): void`.
- `monotonicNowNs(): string` supplies the same native clock for readiness checks.

`FrameKeyJs` is `{session:string, widget:{id:number,generation:number}, allocation:string}`;
session is 32 lower-case hex digits, other strings are canonical unsigned u64
decimal. Never round counters through JS Number. PublishResultJs is
`{status:'published'|'busy'|'stale',seq:string,bytes:string}`; errors throw a stable
diagnostic outside the paint loop, which retains damage on Busy. BridgeEvent is
`ready` (session), `registered`/`consumed`/`retired` (key, seq for consumed),
`need_baseline` (widget), `swapchain` (generation,width,height,ready),
`progress` (swapchainGeneration,completedDraw,monotonicNs; decimal u64 strings),
or `disconnected`/`unavailable` (reason). `ready` alone is not capture readiness.
BridgeStats has decimal counters `cpuBytes, publications, coalescedHints,
livePixelBytes, retiredPixelBytes`; Electron records extraction bytes/time separately.
