## Operator commands

Build explicit production artifacts without launching or installing anything:

```sh
scripts/render-4-build.sh
python3 scripts/render-4-check.py --automated --output target/render-4/automated
python3 scripts/render-4-check.py --gpu --output target/render-4/gpu
python3 scripts/render-4-check.py --inventory --pid "$PID" --output target/render-4/inventory
```

Inventory is read-only. It records PID/start ticks, loaded mappings, related
Underwolf processes, artifact hashes, Vulkan/desktop output and limitations.
Focus, game settings and whether the whole sample was uncapped require explicit
operator evidence. No cleanup by game/process name is performed.

Installation is a separate explicit operator action:

```sh
scripts/render-4-install.sh --output target/render-4/install-record
scripts/render-4-install.sh --restore target/render-4/install-record/install.json
```

Only `underwolf-render-4.json` and a content-addressed production library are
written. A prior owned manifest is backed up; restoration refuses a changed
installation. Existing spike manifests are preserved. The installed layer needs
`UW_LAYER_ENABLE=1` in the individual game launch environment, still checks the
game identity, and respects `UW_LAYER_DISABLE=1`. Installation was exercised only
inside an owned temporary data directory, including update/restore and a preserved
spike sentinel. No release installation has been run.

With an explicitly coordinated target, start the fixture from the repo root:

```sh
npm start --prefix tools/render-fixture -- \
  --pid "$PID" --start-ticks "$START_TICKS" \
  --input-command "$PWD/scripts/render-4-launch.sh" \
  --scenario benchmark --copy-mode dirty --image-mode retained-full \
  --output "$PWD/target/render-4/live-fixture"
```

The launcher verifies the process incarnation and uses explicit production
`uw-inject`, `uw-helper64.exe`, `uw_bootstrap64.dll` and `uw_overlay.dll` paths.
It does not invoke legacy injectors, a TCP input server or layer input filters.
Use `--scenario input` for diagnostics and `--scenario small-damage` for sparse
changes. Ctrl+Tab controls exclusive mode; Ctrl+F10 cycles the second input
widget's block/pass/notify policy. Dimming follows actual accepted capture state.
Operator stdin also accepts JSON commands `enter_edit`, `leave_edit`, `takeover`,
`release_takeover` (with a target), `mode` (with block/pass/notify), and `stop`.
The fixture never automatically requests capture on reconnect.

## Measurements and report manifest

Set `UW_RENDER_TRACE_DIR` and `UW_RENDER_STATS_DIR` to fresh owned directories in
**both** game launch environments. Tracing uses an 8192-sample try-lock queue;
only the background writer touches CSV/files. Any contention/capacity drop makes
a trace invalid. `<pid>-<device>.csv` contains `present_ns,interval_ns,submitted`;
the first interval is zero. The matching JSON contains PID/incarnation, complete
status, sample/submitted/skipped/drop counts. Clean device teardown closes the
trace; crashed/running/truncated traces cannot pass. Native resource/upload
metrics and fixture extraction/copy/time/coalescing/pending/consumption-receipt
lag counters are separate. Receipt lag includes channel/poll delay and is an
upper bound on GPU completion latency.

For normal and maximum-settings scenarios collect three complete 60-second
pairs, in AB/BA/AB order, uncapped and focused, with at least five seconds after
the full workload is ready. Every arm uses a **fresh process incarnation**. A
loads the same instrumented inactive production layer, with no host/helper and
neither bootstrap nor input DLL ever injected. B has all three widgets, the
400x300 animation at 60 FPS, two 300x200 static widgets, copies, layer and production
input active in standard mode. Stopping a helper does not make an injected process
an A baseline. Record module inventories, settings/resolution/scale, hashes,
foreground/cap observations and disturbances for each run. Restore any temporary
settings and leave the session in the agreed state.

The report reads only explicitly listed files:

```sh
python3 scripts/render-4-report.py --manifest target/render-4/runs.json \
  --output target/render-4/performance.json
```

Manifest schema 1 has `implementation_head`, `artifacts` (same exact hash mapping
for all runs), `environment`, `scenarios:["normal","max"]` and `runs` in collection
order. Each run contains:

| Field | Contract |
|---|---|
| `scenario`, `pair`, `arm` | normal/max, 1–3, A/B; AB/BA/AB order |
| `process` | positive `pid`, canonical decimal `start_ticks`; matches native trace metadata |
| `source_head`, `artifacts` | exact manifest source/hash mapping |
| `trace`, `trace_meta` | explicit paths relative to manifest or absolute; never a glob/reused trace |
| `settings` | identical within a scenario, including `preset`, `resolution:[width,height]`, positive `scale` |
| `workload_ready_seconds` | offset from first present at which the entire arm workload was ready |
| `warmup_seconds`, `sample_seconds` | sampling starts at this trace offset, at least 5 seconds after workload readiness; duration 60 |
| `focused`, `uncapped`, `disturbed` | true, true, false for the whole sample, from operator evidence |
| `previously_injected`, `spike_loaded`, `capture` | all false |
| `production_layer_loaded` | true in both arms |
| `input_loaded`, `bootstrap_loaded`, `host_active`, `helper_active` | all false in A; all true in B, verified from raw inventory/session evidence |
| `widgets`, `animation_fps` | A:0/B:3; animation fixed at 60 |

Per-run FPS is frames divided by elapsed interval time; p99 is nearest rank.
Scenario summaries are the arithmetic means of the three run summaries, matching
`spikes/common/src/stats.rs`. Individual paired comparisons are retained. The
aggregate must pass **both** FPS loss and p99 increase <=3.0%, tolerance 1e-9.
A measured failure stays a failure; do not reduce widget FPS or switch to GPU
shared textures to rescue this gate on the current plan's authority.

Performance facts supplied in the manifest are operator attestations backed by
raw inventories/observations, not facts inferred from portable tests. Owner visual
and production-input observation is supplied separately as `owner_observation`;
other gates use `gates`, with `status`, `source_head`, existing `raw` file paths and
scope. Missing owner evidence remains pending, missing AMD/GPU-bound evidence
unavailable. A generic portable pass cannot manufacture those results.
Full-versus-dirty, sparse/full-damage cost comparison uses the same HTML/build
and remains a separate `transport_comparison` gate.

## Execution decisions

These are the recorded rulings, in execution order. Their limitations remain in
force while the live gates are open.

- Task 3: Ruling: mark FrameMapping::open and writable descriptor export unsafe — byte/header validation cannot prove that arbitrary shared native pthread bytes are initialized or that external writers honor synchronization — callers must explicitly uphold the native IPC ownership contract; product behavior is unchanged.

- Task 3: Ruling: add budget-aware create_in/open_in constructors alongside standalone constructors and keep each reservation inside its mapping — retired Arc/GPU references must remain charged to the session budget — session consumers must use these constructors or combined allocation accounting would be incomplete.

- Task 3: Ruling: dedicated endpoints use an advisory owner lock and inode-checked unlink — this permits safe stale-socket recovery after a host dies while refusing live endpoints — one tiny lock file persists per process incarnation; removing a lock file with existing waiters would break exclusivity.

- Task 5: Ruling: use arc-swap 1.9 for immutable device-dispatch snapshots — present must forward the real game call even while another device is created/destroyed, without blocking on a global map mutex — one small production dependency is added; resource-state access still uses try-locks.

- Task 5: Ruling: require Vulkan 1.1 or newer for rendering and append supported surface-maintenance instance dependencies with fallback — EXT swapchain-maintenance1 also requires EXT surface-maintenance1/KHR get-surface-capabilities2; the plan did not spell out that dependency — Vulkan 1.0 applications retain their original create calls and rendering stays unavailable.

- Task 5: Ruling: a driver-attempted but failed queue submission quarantines its assets/leases until device teardown — device-loss errors cannot safely establish that imported bytes are no longer referenced — the path becomes unavailable and retains bounded resources rather than reuse pixels on an ambiguous failure.

- Task 6: Ruling: replace the proposed host-released VkEvent delay with a probe-only host-signalled timeline-semaphore gate — current Vulkan VUID 09543 forbids vkSetEvent while a waiting command buffer is pending; actual validation reported the violation — the optional probe now requires timeline-semaphore support, while production requirements and transport remain unchanged. Both primitives establish a real delayed GPU read; the timeline gate gives valid bounded host release.

- Task 6: Ruling: keep the host-released timeline delay in the offscreen real-channel test, rather than the WSI binary-semaphore chain — VUIDs 03238/03268 require transitive binary-wait signal dependencies to have been submitted, so a future host signal cannot legally hold that present chain — the offscreen GPU case now disconnects/reconnects the actual ProducerSession socket, registers resized/replacement allocations during the delayed read and renders the retained final static image. The compiled-layer WSI test covers 100 real reconnect/resize cycles and a paused unsubmitted claim, without a synthetic GPU stall.

- Task 7: Ruling: after render loss invalidates queued/awaited mutations, keep that input epoch hidden and withhold all further lease acknowledgements until a fresh native input epoch — discarded events cannot truthfully be reported consumed; the existing bounded native restoration handles the gap — recovery waits for the native session to renew, with no automatic recapture.

- Task 8: Ruling: per-run FPS is frame count divided by total interval time, then scenario FPS is the arithmetic mean of three run summaries — this matches the binding spikes/common stats reference; averaging reciprocal individual intervals would overweight short frames — jitter-heavy comparisons would differ if that interpretation were wrong.

- Task 8: Ruling: the current owned WSI probe CPU-fences its game rendering and supplies no game-owned present wait semaphores — Vulkan gives no image-reacquisition fairness guarantee, so a fixed iteration drain cannot prove their release; the production layer still uses its real binary signal and independent maintenance present fence, unchanged — current WSI runs have weaker game-wait coverage, so separately retain the earlier clean real game-wait run only after checking the production layer binary hash is identical. Live game synchronization still needs acceptance. Official basis: https://docs.vulkan.org/guide/latest/swapchain_semaphore_reuse.html.

- Final: Ruling: live Deadlock/Proton visuals, actual production input recovery and container visibility were set aside by review — they need the coordinated owner session and remain pending acceptance rather than inferred passes — integration without this evidence would leave real-game behavior unverified.

- Final: Ruling: whole-overlay performance, full/dirty comparison, GPU-bound and AMD results were set aside by review — no qualifying measurements/hardware were supplied; keep pending/unavailable gates — shipping without these gates risks unknown performance and hardware regressions.

- Final: Ruling: Windows rendering, additional games, generic app runtime, native Chromium injection and GameInput were set aside — excluded/deferred in the approved phase, with no support claim — these use cases remain unsupported.

- Final: Ruling: inherited color-management redesign was set aside — preserve the binding design's existing UNORM/sRGB pipeline and its exact readback expectations — this phase does not establish a new color-management model.

- Final: Ruling: malicious same-UID pthread corruption was set aside — keep the explicitly unsafe trusted-native IPC contract and identity rejection — deliberately corrupted native storage is outside the supported safety boundary.
