## Implemented behavior

The injected UI owner applies a bounded widget/hotkey table, chooses targets,
and publishes keyboard/mouse ownership only after native setup succeeds.
Tables carry numeric widget ids and generations; v2 u64 counters use canonical
decimal strings across JSON. Block, pass and notify policies and exclusive
capture share the existing restoration journal and game-local delivery lease.
The helper relays application results with exact purpose/epoch/revision/id
correlation. Reconnection republishes only the desired table. Focus, held input,
takeover and edit-on are never replayed.

The fixture's renderer applies directly to the intended widget and resolves
before progress is acknowledged. A disconnected generation cannot mutate the
renderer after an awaited operation resumes. This is fixture consumption, not
native Chromium `sendInputEvent` compatibility. Context7's Electron 44.9.1
[executeJavaScript documentation](https://github.com/electron/electron/blob/v44.9.1/docs/api/web-contents.md)
provides the Promise completion contract used by the adapter.

DirectInput uses real 8A/8W system method detours, acquisition intent and temporary
owned COM references at restoration boundaries. The native exclusive-device
probe demonstrated that thread hooks missed the named hotkey; this justified
the owner-thread low-level fallback. Independent worker-targeted raw-input
and NOLEGACY Unicode-packet probes also demonstrated missing ordinary
messages, so those sources select the same owner stream. It remains scoped to the foreground target,
uses one canonical event stream, and preserves desktop modifier/click delivery.

## Native availability and limits

See [the ABI record](2026-10-25-input-3b-abi.md) for pinned header identities and
discovery contracts. The actual environments are Wine 11.20 and Proton
`proton-11.0-2e-x86_64`, on Linux `7.2.11-1-cachyos`, KDE Wayland, RTX 4090,
driver `615.78.08`. Automated native rendering uses Xvfb; its geometry and
software rendering are not live-game performance evidence.

| Native path | Status |
| --- | --- |
| Win32 legacy/raw/polling/cursor paths | Real Wine regression fixtures passed; owner observations partial, fixed-build focus-return retest open |
| DirectInput 8A and 8W keyboard/mouse | Real custom formats, acquire intent, PEEK/overflow/flush/errors, aliases/lifetime, held quarantine, exclusive hotkeys, partial domains and desktop input checked |
| Pre-existing DirectInput device unseen throughout capture | Real A/W custom-format modifier objects: no captured buffered replay; fresh native state/buffers work after release |

A discovered or unknown present native runtime cannot enable capture without
installed coverage. The object-free `E_NOTIMPL` factory permits already-covered
paths while advertising GameInput as unsupported. This is not GameInput
isolation. No replacement runtime is installed into a player's game.

## Reproduce and launch

Build release artifacts in the implementation worktree:

```bash
cargo build --release -p uw-inject
cargo build --release --target x86_64-pc-windows-gnu \
  -p uw-bootstrap -p uw-helper -p uw-overlay -p uw-test-game -p uw-test-overlay
cargo build --release --target x86_64-pc-windows-gnu -p uw-input \
  --example input_probe --example native_input_probe --example input_sender
```

Run the isolated native suites sequentially:

```bash
xvfb-run -a cargo test -p uw-helper --test wine_input --test wine_routing -- --ignored --test-threads=1
xvfb-run -a cargo test -p uw-input --test wine_input --test wine_routing --test wine_directinput -- --ignored --test-threads=1
python3 scripts/input-3b-native.py --runtime wine --discover
python3 scripts/input-3b-native.py --runtime proton --proton '/path/to/Proton 11.0' --discover
python3 scripts/input-3b-native.py --runtime proton --proton '/path/to/Proton 11.0' --case directinput
python3 scripts/input-3b-native.py --runtime proton --proton '/path/to/Proton 11.0' --case directinput-exclusive
```

The runner requires actual native output plus successful exit, preserves its
artifact hash/logs/JSON, and uses a fresh prefix. Discovery availability is
reported separately from isolation acceptance. Its default evidence directory
is unique per invocation; `--out` must name a new directory.

For an owner-approved Hideout/bot session, follow the
[fixture launch and control instructions](../../../spikes/osr-host/ROUTING.md).
Use the exact intended PID and existing Proton installation, with the game and
host drawing layer configured as `UW_SPIKE_CAPTURE=win32`. The routing mode
starts the production injector, never the C3 spike injector or collector.
Stopping the owned receiver closes the production session; the local lease
revokes capture. The injected DLL stays resident until normal game exit.

## Execution decisions

These recorded rulings are retained in execution order, including their costs
if wrong. Historical staging decisions do not close outstanding acceptance.

- use the repository's existing max_width=120,use_small_heuristics=Max for scoped formatting — verified against the original policy.rs; default cargo fmt rewrites unrelated files, which were fully restored — wrong formatting settings would add review churn, not behavior changes.
- run the console probe with Proton runinprefix and read its PROTON_LOG, rather than Proton run through SteamAppId=0 — the run wrapper returned 0 without executing the probe; explicit JSON evidence prevents false success — wrong invocation would invalidate the runtime evidence.
- run the Xvfb-backed discovery fixtures sequentially — this installed xvfb-run -a checks for a free server number before startup, so concurrent private-prefix runs raced on :99; the failed attempt is preserved and the standalone retry passed — parallel execution would make native evidence inconclusive.
- expose new typed JSON envelopes in routing::json and the dedicated routing hello classifier now, then integrate them into the root helper/host enums atomically in Task 9 — adding root enum variants before their consumers would break otherwise independent task commits — wrong envelope integration would leave the new protocol unavailable, never silently enable capture.
- add optional RoutingCode to RouteEffects — unchanged ownership can mean Applied, stale revision/epoch, Unavailable or NotOwner, so the native layer must not infer a result from a mask change — a wrong result would misreport application/correlation even when capture remains safe.
- epoch reset drops old pending configuration results together with old input — a result whose cancellation delivery was discarded must never claim Applied; the old session is already invalid and later requests correlate by epoch — a missed old result can time out, but cannot falsely confirm committed delivery.
- keep delivery epochs stable for ordinary v2 domain release — pointer ownership may change many times within one healthy routing session; core 3a behavior and safety-failure epoch bumps remain — wrong epoch handling would discard valid releases or require an unnecessary host reconnect per hover.
- add a typed ordered request-result barrier alongside Configured — takeover/focus cancellation must drain before its exact host result, too — wrong ordering would let the receiver confirm focus while old held input remains queued.
- use original successful RIDEV_NOLEGACY intent to select raw versus legacy canonical events per device class — matching complete raw/legacy down/up cycles in real probes fires exactly once; passive raw polling retains native sizes — choosing the wrong source could duplicate activations or miss input.
- retain explicit v2 runtime variants but ignore them in the current v1 overlay consumer until Task 9 wires negotiation atomically — connect_routing is the only v2 entry and legacy connect remains on v1 — a wrong switch would leave routing unavailable, not silently mix protocol versions.
- enable owner-thread low-level keyboard/mouse fallback only after the real exclusive-DirectInput probe proved named hotkeys absent (0 instead of 1, task-7-native-exclusive.log) — standard thread hooks are swallowed by exclusive DirectInput; one canonical source plus foreground scope are required — a wrong fallback could duplicate input or interfere with desktop input. - keep Task 8 native reading/history/callback implementation and acceptance OPEN while continuing independent Task 9 — Task 1 prerequisite (real callable GameInput objects and verified native ABI) cannot be met on installed Wine/Proton, both factories return E_NOTIMPL; the owner explicitly chose to leave GameInput open.
