# Input 3b: native ABI discovery

Status: discovery foundation verified in isolated Wine and Proton processes.
This is not input-isolation or full 3b acceptance. GameInput runtime acceptance
is open: both tested factories return `E_NOTIMPL` (`0x80004001`). The owner has
been asked whether to keep that acceptance open or defer GameInput from 3b.

## Environment and results

The production game and its Wine prefix were not touched. Each probe used a
new private prefix and Xvfb; cleanup addressed only its own wineserver/prefix.

| Runtime | DirectInput | GameInput |
|---|---|---|
| System Wine | 8A and 8W factories and keyboard/mouse method implementations discovered | DLL/export present; factory returns E_NOTIMPL; no interface layout assumed |
| Proton `proton-11.0-2e-x86_64` | 8A and 8W discovered; independent pre-existing device reads unchanged | Same E_NOTIMPL result, confirmed through independent factory declarations |

The final probe SHA-256 is
`81621bd1fdf1b52082c2d5cf7c4382a617bf643199785f479b4e3f2c1d202cc2`.
It reported 40 target descriptors, including compatible aliases. Discovery
does not install detours or acquire game devices. Captured input, buffered
suppression and callback isolation remain later native-adapter tests.

Local evidence lives in the implementation worktree's
`target/input-3b-native/final-wine/` and `final-proton/`: `result.json`, stdout,
stderr and the Proton log. Early/incomplete attempts remain separately saved.
One concurrent Xvfb run was rejected after the shared-server-number race left
the wrapper exiting 1; the separate Proton retry exited 0 with actual JSON.

Proton's `run` verb with SteamAppId 0 returned 0 without executing the probe.
The verified invocation uses `runinprefix` and `PROTON_LOG=1`; application
stdout is in `PROTON_LOG_DIR/steam-0.log`. A wrapper's exit code alone is not
probe evidence: require one parsed JSON record and the successful wrapper exit.

## Public ABI source

GameInput declarations use Microsoft's public header revision
`dce6dabd75b53fcb29db86afe4de5c917921af18`:

| Interface version | Header | Header SHA-256 |
|---|---|---|
| v0 | `include/v0/GameInput.h` | `4bda852f78a43f715837c1d97af7cf78fa14aa35dba4e755d305985364bf1196` |
| v1 | `include/v1/GameInput.h` | `66749881268ecf4c470401c92872e9dc4041ebbf6dfcff95fcbae2e0fab03b80` |
| v2 | `include/v2/GameInput.h` | `2df7aa891696c72e1c7e6e3570e8aa3b2cc5629aefe5ae614386b5ad087f0830` |
| v3 | `include/GameInput.h` | `17e83b2de0fd074ed2faca8ca3bbc88a5a074ca2672cabc2afe9c38ee61064f1` |

The four IGameInput IIDs are respectively
`11BE2A7E-4254-445A-9C09-FFC40F006918`,
`40FFB7E4-6150-407A-B439-132BADC08D2D`,
`BBAA66D2-837A-40F7-A303-917D500955F4`, and
`20EFC1C7-5D9A-43BA-B26F-B807FA48609C`.
The export returns the legacy interface; only successful QueryInterface may
select a versioned layout. Unknown IIDs are never used to dispatch assumed slots.

Notable signature differences: v0 reading registration has an analog-threshold
float and its callback has an overrun bool. Later reading callbacks have three
arguments and registration omits that float. v0 UnregisterCallback takes a
timeout in **microseconds**; later versions omit the timeout argument. All
callbacks and methods use the system calling convention. The current runtime
did not provide an object, so these versioned declarations are not advertised
as runtime-verified isolation.

DirectInput declarations follow the installed Windows SDK-compatible MinGW
`dinput.h`: 8A/8W factories, CreateDevice, IUnknown lifetime, Acquire/Unacquire,
GetDeviceState/GetDeviceData, SetDataFormat and SetCooperativeLevel. The probe
declares its own dispatch types and creates devices before discovery; its
unacquired immediate-read results are identical afterwards. Device/data-format
and buffered-read isolation are still Task 7's gate.

`OwnedCom` owns exactly one factory/QueryInterface reference and releases it
through its original Release. Borrowed game pointers are not converted into
owning projected objects. Published target modules are pinned before their
addresses escape discovery. Compatible shared targets register once;
incompatible reuse, null targets and growth beyond 256 are rejected.

## Commands and verification

Build from the isolated implementation worktree:

```sh
cargo test -p uw-input --test native_discovery
cargo build --release -p uw-input --target x86_64-pc-windows-gnu --example native_input_probe
cargo clippy -p uw-input --all-targets --target x86_64-pc-windows-gnu -- -D warnings
```

Run `native_input_probe.exe --discover --directinput --preexisting --late-load`
in a new Wine prefix under Xvfb. For Proton use the same executable/flags with
`proton runinprefix`, a separate `STEAM_COMPAT_DATA_PATH`, the Steam client
installation path, and `PROTON_LOG=1`. Run these Xvfb fixtures sequentially.
`--gameinput` explicitly requires available GameInput and therefore fails in
the tested runtimes; omitting it does not turn its acceptance into a pass.

Six portable discovery tests were observed failing before their implementation
and then passing. The existing Windows export-target unit test also ran in a
fresh Wine prefix: one passed, zero failed. The post-change workspace suite
passed 576 tests with zero failures and 64 opt-in cases ignored.
The existing workspace baseline had 570 passing tests and
64 opt-in tests ignored. Full post-change workspace results are tracked in
the task ledger; opt-in native discovery is separately qualified above.

Context7 was used for MinHook creation/lifetime rules and Rust Windows binding
ownership. Its GameInput queries returned unrelated material; the pinned
[Microsoft headers](https://github.com/microsoftconnect/GameInput/tree/dce6dabd75b53fcb29db86afe4de5c917921af18/include)
provided the ABI declarations. MinHook detours remain disabled/unimplemented
in this discovery task.
